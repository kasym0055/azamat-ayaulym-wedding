# Азамат & Аяулым — мобильное приглашение

Публичная версия: [kasym0055.github.io/azamat-ayaulym-wedding](https://kasym0055.github.io/azamat-ayaulym-wedding/).

Готовый сайт состоит из `index.html`, `styles.css`, `script.js`, папки `assets/` и файла `supabase-setup.sql`. Он работает без сборки и без тяжёлых фреймворков. Для просмотра откройте `index.html` через локальный HTTP-сервер или разместите все файлы на статическом хостинге. Открытие двойным щелчком тоже покажет страницу, но некоторые браузеры ограничивают загрузку медиа с `file://`.

## Файлы

```text
index.html
styles.css
script.js
supabase-setup.sql
README.md
assets/
  hero-background.jpg
  restaurant.jpg
  baqyt.mp3
  og-image.jpg
  favicon.svg
```

В поставку уже включены присланные вами фотографии и аудиофайл. Используйте эти файлы только в рамках прав, которыми вы располагаете. Музыка никогда не запускается автоматически: гость нажимает кнопку вверху страницы, а первое воспроизведение начинается примерно с 00:16. После паузы воспроизведение продолжается с текущего места. При отсутствии аудиофайла сайт остаётся работоспособным.

## Замена фотографий и музыки

Замените `assets/hero-background.jpg` своим вертикальным свадебным фото. Лучше использовать пропорции около 2:3 и размер хотя бы 1000×1500 px. Для фотографии ресторана замените `assets/restaurant.jpg`; широкое фото 16:9 или близкое к нему выглядит лучше всего. Сохраняйте имена файлов и оптимизируйте изображения для веба. `assets/og-image.jpg` — изображение для превью ссылки; сейчас там копия первого фото. Для красивого превью в мессенджерах замените её отдельной широкой открыткой. Если убрать фотографию ресторана, вместо сломанного значка появится спокойная текстовая заглушка.

Чтобы заменить песню, положите MP3 в `assets/baqyt.mp3`. Начальная позиция задаётся переменной `MUSIC_START_TIME` в `script.js` (сейчас `16`). Для новой песни при необходимости измените это число. Звук запустится после нажатия гостя, поскольку мобильные браузеры блокируют автоматическое воспроизведение со звуком.

## Ссылка 2GIS

В `script.js` есть понятная переменная `TWO_GIS_URL`. Точная ссылка, которую вы прислали, уже вставлена. Для замены поменяйте только её значение. Кнопка сразу под фото откроет 2GIS в новой вкладке. Адрес текстом меняется в секции локации файла `index.html`.

## Подключение Supabase для ответов гостей

Проект Supabase уже подключён: его URL и публичный publishable key записаны в `script.js`. Таблица `wedding_rsvps` существует; публичное чтение ответов закрыто, а недопустимые значения отклоняются. Форма отправляет ответы без перезагрузки страницы. Ниже — порядок настройки при переносе приглашения в другой проект.

1. Создайте проект на [Supabase](https://supabase.com/dashboard). Дождитесь окончания его настройки.
2. Откройте **SQL Editor**, вставьте содержимое `supabase-setup.sql` и выполните запрос. Он создаст таблицу `public.wedding_rsvps`, ограничит допустимые значения и включит Row Level Security. Посетителю доступна только вставка своего ответа; публичное чтение, изменение и удаление записей запрещены.
3. В панели проекта найдите **Project URL** (обычно в **Connect** или **Settings → API**). Он выглядит как `https://<project-ref>.supabase.co`.
4. Там же скопируйте **publishable key** (`sb_publishable_...`) или legacy **anon/public key**. Это публичный ключ для браузера. Не используйте secret или `service_role` key: они дают повышенные права и не должны попадать во frontend.
5. При переносе в другой проект в самом начале `script.js` замените значения `SUPABASE_URL` и `SUPABASE_ANON_KEY`. Имя второй переменной оставлено в соответствии с заданием; в неё вставлен современный publishable key.
6. Опубликуйте обновлённые файлы. Для проверки заполните форму, затем откройте **Table Editor → wedding_rsvps** в Supabase. Там владелец проекта видит список гостей, ответы и время отправки.
7. Для экспорта откройте таблицу в **Table Editor** и используйте её меню экспорта CSV; расположение команды может меняться с обновлениями панели. Альтернативно выполните SQL-запрос в SQL Editor и экспортируйте результат:

```sql
select guest_name, attendance, created_at
from public.wedding_rsvps
order by created_at desc;
```

Значения `attendance`: `alone` — один гость, `with_partner` — с партнёром, `cannot_attend` — не придёт. Современные ключи и принцип работы RLS описаны в [документации Supabase по ключам](https://supabase.com/docs/guides/getting-started/api-keys), [RLS](https://supabase.com/docs/guides/database/postgres/row-level-security) и [REST API](https://supabase.com/docs/guides/api). Публичная форма доступна любому посетителю страницы, поэтому при широком распространении ссылки стоит периодически просматривать ответы на дубликаты или спам.

## Публикация

Загрузите `index.html`, `styles.css`, `script.js` и папку `assets/` в корень любого статического хостинга, который поддерживает HTML/CSS/JS, например Netlify, Cloudflare Pages, GitHub Pages или обычный веб-хостинг. SQL-файл и README не нужны в публичной директории. После публикации откройте ссылку с телефона и проверьте музыку, 2GIS и отправку формы. Для работы Supabase нужен доступ браузера к его HTTPS API.

В `index.html` заполнено название, описание и Open Graph metadata; `og:image` указывает на абсолютный адрес GitHub Pages. При переносе на другой адрес обновите это значение. После переноса проверьте музыку, 2GIS и отправку формы на опубликованной странице.
